## 统一计算引擎 · 收尾两项遗留边界（已实现并通过验证）
承接 11-16 第 1/2/3 步，本日闭环此前明确记录的两项遗留：

### 边界一：整数分精确乘法，消除 `1.005*3=3.01`
- `common/calc/amounts.ts` 新增 `mulDecimal(a,b,digits)`：把两因数按十进制字符串拆成「整数尾数 + 小数位数」，用 **BigInt 整数相乘**后再还原小数并交 `money.round` 舍入，全程不做浮点乘法。入参经 `decimalOf` 归一，吃 number/string/Prisma Decimal/科学计数法；空/非法返回 null；半值远离零口径不变。
- `calcAmount`/`calcPriceWithTax`/`calcTotalWithTax` 全部改走 mulDecimal；前端 `procurementPriceCompare.ts` 的 calcAmount 本就委托共享实现，自动同步，无需改前端。
- 为什么不用浮点：旧 `(1.005*3)` 的 double 是 3.0149999999999997，任何 round 都得 3.01；整数分按十进制算 3.015 → 3.02，与 Excel ROUND 一致。TS target server ES2021 / web ES2020，BigInt 两端均支持。
- 测试：`money.spec.ts` golden case 由 3.01 改 3.02 并加 mulDecimal 边界用例（负数/科学计数法/0/非法值）；`frontendChainParity.spec.mts` 加双端 3.02 断言。

### 边界二：逾期台账读时重算，消除派生列陈旧值
- 根因：派生列（overdueDays/overdueInterest 等）此前只在增删改时重算并持久化，之后未付完的剩余金额本应继续计息，库内值却停在上次写入日 → 台账陈旧。
- `overdue-calculator.ts` 新增纯函数 `recomputeOverdueRows(rows, opts)`：走**同一个 recalculate 引擎**按 asOfDate 现算，把派生列覆盖到每行返回；无派生值的行用 EMPTY_DERIVED 置空（与写库 `?? null` 口径一致）。不写库，库内列退化为写入快照。
- `finance.service.listOverdue` 改为读时重算：①先全量取行（付款分配跨月，禁止先按 settlementMonth 过滤，否则漏跨月片段）→ 重算 → 再按月份过滤（保持"筛选视图只汇总筛出行"语义，但读的是重算新值）；②input 展开原始行保留 monthlyRate/version/createdAt 等字段并归一 Decimal；③asOfDate 由 service 边界取一次注入，新增可选参数供单测/定时刷新复现任意时点。
- 导出 `exportOverdue` 走 listOverdue，自动受益；dashboard/ledger 读的是 payableAmount（与时间无关的写时稳定值）或 count，不受陈旧值影响，故无需改。
- 测试：`overdueCalculator.spec.ts` 新增 describe，验证覆盖陈旧值、利息随 asOfDate 单调增长（59/89/119 天 → 118/178/238）、无派生行置空、stats 与引擎 deepEqual。
