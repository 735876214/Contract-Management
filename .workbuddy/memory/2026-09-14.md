## 修复 CI 构建失败：prisma CLI 被 --omit=dev 跳过（exit code 127）
- **现象**：Actions `buildx` 失败 —— `process "/bin/sh -c ... ./node_modules/.bin/prisma generate ..." did not complete successfully: exit code: 127`；日志细节 `/bin/sh: 1: ./node_modules/.bin/prisma: not found`。frontend job 一直成功，只有 backend 失败。
- **根因（关键坑）**：`npm install --no-save --omit=dev prisma@^5.10.2` 无效 —— prisma 在 package.json 里**本身就是 devDependency**，
  npm 认为该 spec 已被满足，只输出 `up to date in 1s`（前一步 `added 298 packages`），**根本没装**，
  于是 `node_modules/.bin/prisma` 不存在。（`--omit=dev` 下，npm 对「显式指定但属于 devDependencies 的包」仍按 dev 处理并跳过。）
- **修复**：proddeps 阶段安装前用 `node -e` 把 `devDependencies.prisma` 临时挪到 `dependencies`，再一次性 `npm install --omit=dev`；
  并在 deps / proddeps 两处加 `test -x ./node_modules/.bin/prisma || (echo ... && exit 1)` 断言，失败时给可读错误而不是 127。
- **验证**：推送后 Actions run 34771391416 两个 job 全绿 —— proddeps `added 304 packages`（+6 即 prisma CLI）、
  `Generated Prisma Client (v5.22.0)`、nest build 通过。ghcr 压缩层体积：cms-backend 115.8MB(11层)、cms-frontend 28.4MB(10层)。
- **取 CI 日志的可用办法**（本机无 docker / 无 gh 客户端）：GitHub REST API + PAT，日志下载会 302 到 Azure Blob，
  必须**在重定向时摘掉 Authorization 头**（否则 401）；run/jobs 列表用 `/actions/runs/{id}/jobs`，日志用 `/actions/jobs/{id}/logs`。

## 事故：git pull --rebase 被中断导致本地对象库损坏（已恢复）
- 提交后执行 `git pull --rebase origin main`，进程被 SIGTERM 强杀，留下 `.git/rebase-merge` 空目录，
  `refs/heads/main` 指向**不存在**的对象，随后 `git log`/`git fsck` 报 `bad object`，且今天的若干对象（e27a1b1 等）丢失。
- 恢复步骤（有效）：`rm -rf .git/rebase-merge` → `git update-ref -d refs/heads/main` → `git fetch origin main`
  → `git update-ref refs/heads/main $(git rev-parse FETCH_HEAD)` → `rm -f .git/index && git reset --mixed HEAD`（重建索引，工作区不动）。
- **教训**：本环境不要用 `git pull --rebase`（易被中断且会留半损状态），改为「fetch + update-ref/reset」分步操作，且先备份改动文件。
- 另发现：本工作区 `server/src` 的 11 个文件内容等于 `e27a1b1`（旧），而远端 `0c66afa` 是用户在别处提交的新版本 —— 本工作区从未检出过它，
  因此 `git status` 会显示这 11 个文件「被改动」（实为旧版本）。**未擅自还原**，已在回复中提示用户按需 `git restore --source=HEAD -- server/src`。
