# 产品口径（业务决策登记）

> **何时加载**：实现/改动任何业务功能前，或对"该不该做某机制"拿不准时。
> 这些是业务方拍板的决策（2026-10-16 起陆续确认），**不要重新提议**；细则与技术落点见
> [backend-conventions.md](backend-conventions.md) 与对应工具的文件头注释。

## 流程与单据

- **无多级流程引擎**：合同流转就是 `status`（草稿中 → 待签章 → 已签章）+ `/sign` + `/reject` 状态回退；
  不做可配置流程，代码与文档里不再使用"审批"这一说法。
- **付款只有单表台账** `PaymentRecord`（登记**已完成**的付款），**不做**「计划 / 申请 / 核销（三单匹配）」。
- **付款不与结算/发票关联**，只在**超付款比例**时工作台预警（开累付款 > 开累结算 × 生效比例）。
- **总结算单收口**：抓取该合同全部月度结算生成明细快照（一合同一张）；**附件上传完成即「已结算」** →
  合同 `execStatus = DONE_SETTLED` → 付款比例切 100%；删除已结算单据一并回退。
- 单据模板五类里接了 **Excel 生成路径**的是**付款单与总结算单**；其余（结算单/保理单/逾期利息）本期只做模板存放。
- **采购订单与对账由外部系统承接**（业务 2026-10-18）：本项目**不建** `PurchaseOrder` / `Reconciliation`；
  合同与外部订单的对应关系默认由合同附件/备注承载。采购任务 → 合同 → 收领单 的链路不变。
- **总日报是结算的前置与明细来源**（业务 2026-10-18）：**有总日报之后才生成结算单**；
  结算明细**从总日报带出（按物资聚合），允许人工修改**；带出后是结算单自身的可编辑快照。
  收领单推送的行与**手工录入的日报行同属来源**，现场确认过滤（`settlement.require_confirmed`）照常生效。
- **不引入** Flowable / Redis / MQ / 物化视图 / DB 枚举（决策留痕见 `git log`，原评估文档 docs/05 已删除）。

## 金额与变更

- **变更靠补充协议链表达并结构化**：**合同当前金额 = 主合同金额 + Σ 补充协议 `changeAmount`（带符号增量）**；
  工作台对超限出红/黄**预警**——**只展示、不拦单据**，拦不拦由系统参数
  `settlement.over_amount_policy` / `payment.over_amount_policy`（BLOCK/WARN/OFF）决定。
- **付款安排决定付款比例**（合同上二选一）：`M65_1`（次月 30 日前付 65%）或 `M65_3`（次/次次/次次次月
  20-20-25，合计仍 65%）；**总结算完成后按 100%**；存量 `100` / `3382` **保留不动**。
  「当前生效比例」`ContractExt.currentPayRatio` 是**服务端派生列**——台账列、逾期引擎、工作台预警都读它，
  不要界面手填。

## 结算期与关联

- **结算按「月度结算期」组织**：期 = 起始日（`Project.settlementStartDate`）→ 下月同日的前一日
  （起始日 1 日即自然月；26 时期跨自然月）；**发票与收领单都按结算期归属结算单**（一结算单可对多张），
  台账开票额按**关联**归集。本期结算由**手动按钮**生成（从上一期总日报带出明细；当前实现按“期内未挂结算单的
  收领单”聚合，口径对齐见 [document-relationships.md](document-relationships.md) §4），**不引入调度器**。
- **合同正文导出取签订时快照**（`Contract.supplierSnapshot`，签章时冻结）——"历史合同再导出不被主数据改写"，
  不是把供应商信息冗余进合同。

## 四域扩展剩余任务（2026-10-18）

- **合同履约进度是零表派生视图**（已实施）：由总日报/收领单、结算、付款、发票聚合，**不反写**任何单据；
  节点/里程碑表 `ContractFulfillment` 属按需项。
- **合同归档单向**（已实施）：不提供解除归档；归档前检查下游完整性，归档后锁合同/收领单/结算/总结算的写操作，
  **不锁发票/付款/读取/导出**——业务 2026-10-18 明确：**归档后允许补录发票/付款**（归档检查给 warning）。
- **进出场只做物资**（已实施）：复用 `ReceiptOrder` / `DailyReport` / `AssetLedger`，不建新表；
  资产台账支持进出场方向筛选与汇总（费用行只计金额、不混入数量）；不做人员/车辆/门禁/扫码。

## 成本管理（2026-10-17 附件需求批次）

- **分包单位领用月度汇总**（`/cost/labor-receiving`）：一行 = 分包单位 × 结算期 × 材料；
  **本期领用与平均单价从收领单明细自动聚合**（只读），退库/库存盘点/设计量开累/损耗率手填；
  导出三表（月度盘点 / 领用月度汇总 / 甲供材节超分析）。旧手工台账「分包领用汇总」已删除。
- **月度盈亏分析**（`/cost/profit-loss`）：**一个月一条记录**；新建时把当期各分包单位节超分析行
  **快照**成明细（单价/数量冻结，历史不变）；手填项 = 明细行责任人/劳务计价已扣/备注、
  六项降本创效金额、劳务计价累计扣款金额；导出封面/明细/汇总三 sheet（汇总按材料跨队加权）。

## 界面形态（2026-10-17 业务确认）

- **「新增」的动作形态按复杂度二分**：业务单据类模块的新增/编辑进**编辑器页签**
  （`?editor=new|<id>`，规则见 [frontend-conventions.md](frontend-conventions.md)）；
  **两类有意保留弹窗/抽屉**：① 基础配置类 6 个模块（字典 / 用户角色 / 合同模板 / 条款 / 单据模板 / 采购模板，
  低频简单表单）；② 「新增补充协议」是**向导型动作**（选类型 → 生成草稿 → 发布，
  `ContractQuery` 的 `SupplementDraft` 抽屉 + 合同详情里的简易补充协议弹窗）。
  如后续要统一改页签，需业务重新拍板。

## 系统能力边界（2026-10-17 业务确认，不要重新提议）

- **不做响应体字段级打码**：系统不做"哪些角色看不到哪些字段"的展示脱敏
  （操作日志的敏感信息脱敏**保留**，那是审计合规，与展示口径无关）。
- **不做行级数据权限（DataScope）**：本项目无"同项目内不同人可见范围不同"的要求，
  数据隔离只有**项目**一级。
- **不做供应商门户 / 外部账号体系**：不建外部账号、不做注册端点（`docs/05` §11 的"放最后"到此为止——明确不做）。
- **不做企微/钉钉通知通道与免登 SSO**（2026-10-18）：无凭据与出网条件，站内信满足现状；
  不为将来可能的外部通道预留抽象层。
- **不做多副本部署**（2026-10-18）：单实例部署是最终形态；共享文件存储、进程内缓存一致性、
  合同编号竞态等前置不再推进。
- **不做移动刚需页 H5 精简版**（2026-10-18）：现有响应式 V1 视口层 + V2 容器层已覆盖移动端
  基本可用（规则见 [DESIGN.md](../../DESIGN.md) §10），不再单出 H5 版本。
- **合同台账维护页**（`/contracts`）**补回菜单入口**（「合同管理 → 合同台账维护」）：
  该页是列表+编辑器页签形态，承接起草页「继续编辑」；与「合同查询」并存（查询偏只读，维护可增删改）。

## AI 服务配置（2026-10-20 业务确认）

- **全站一套上游配置**，不做按项目/按人多套，也不做「全局 + 项目覆盖」：管理员在
  **系统管理 → AI 信息登记**（`/system/ai-register`）登记一次，扫描 / 文件登记 / 汇报材料都读同一份。
- **页面登记优先于环境变量**（逐项回落：页面 > `AI_*` env > 默认）：页面值存 `SysParam`，
  **保存即生效、不用重启**；老部署只配 env 的行为不变。这与「不做可配置流程引擎」不冲突——
  它只是把「改一次 AI 地址要改 compose 再重启」这件事收进界面。
- **密钥只写不读**：任何接口都不回显明文，页面只能显示「已保存」，要换就整把替换；
  「留空保存」= 不修改，清除密钥是独立按钮。
- **超时/配额等调优项不进页面**，仍只认 env（管理员不需要、也不该在界面上改限流）。

## 本地文件存储（2026-10-18 业务确认）

- **附件只保存在本地磁盘**，不引入 S3/MinIO 等对象存储；对外 URL 固定 `/api/files/<相对键>`，
  不改数据库字段/前端链接。
- **文件清理采用「只读审计 + 人工确认」**：不自动删除任何文件；重签/删除业务行产生的孤儿文件
  由 `server/scripts/storage-audit.mjs` 盘点后人工处理。结构说明见
  [docs/local-storage-structure.md](../../docs/local-storage-structure.md)。
- 通用上传收敛到 `StorageService.save()`：单文件 ≤50MB、单请求 ≤10 个，拦截 html/svg/js/exe 等
  可执行/可脚本类型。
