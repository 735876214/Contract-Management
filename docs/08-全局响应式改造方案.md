# 08 · 全局响应式改造方案

> **文档状态**：2026-10-13 制定；**同日已完成阶段 1–4 实施**（见 §0.1 实施记录，实现口径以代码与
> [DESIGN.md](../DESIGN.md) §10 为准）。§1–§6 保留原始方案原文，便于对照「方案 ↔ 实现」的差异。
> 目标：把"**响应式栅格 + 非响应式布局**"的现状，改造为**布局/组件全响应式 + 表格分级降级**。

## 0. 改造前基线（2026-10-13 实测 · **当时快照**）

| 层 | 现状 | 改造必要性 |
|---|---|---|
| 表单/筛选栅格 | ✅ 155/193 个 `<Col>` 已带断点（`xs=` 155 · `md=` 126 · `lg=` 21 · `sm=` 4 · `xl/xxl=` 0） | 补 36 处固定 `span` |
| 断点监听 | ❌ **0 处**（无 `useBreakpoint` / `matchMedia` / `window.innerWidth`） | **需新增基建** |
| 布局 / 侧栏 | ❌ 手动折叠按钮，**不按屏宽自动**；无 Drawer 兜底 | **核心改造** |
| 表格 | ❌ 固定宽横向滚动（`scroll={{ x: 800…1950 }}`，台账 **36 列**） | **核心改造（分级）** |
| 弹窗 | ❌ 65 处 `Modal` 固定宽（如 1000 / 1180） | 统一改造 |
| 全局样式 | ❌ 仅 1 条媒体查询（`index.css` 768px，只调 padding） | 扩展 |

> 结论：**"各界面和模块使用响应式布局"目前不成立**，准确表述为"表单区域用了响应式栅格，布局与数据展示层未做响应式"。

**与原始方案的差异（有意取舍）**

1. **弹窗宽度未逐处改 `width`**：方案 §L4 建议 65 处逐个改响应式宽度。实测只有 7 处显式设宽，
   改为全局 CSS 兜底（`max-width: calc(100vw - 16px)`）覆盖全部 65 处且不会遗漏新增弹窗；
   亦未统一加 `centered`（纯视觉变动，与响应式可用性无关，避免大面积位移）。
2. **编辑器工具栏用「更多」展开而非下拉**：方案 §L5 建议折叠为「更多」下拉。因工具栏含
   `Select`/`Popover` 等有状态控件，塞进菜单项交互不稳，故实现为「高频项常驻 + 更多展开下方低频项」，
   宽屏行为与改造前完全一致。
3. **大宽表（36 列台账）未卡片化**：与方案 §5 的取舍一致，保留横向滚动 + 冻结关键列。

**验证（2026-10-13 实测 · 当时快照，勿当现状）**

- `cd web && npm run build`（含 `tsc --noEmit`）、`cd server && npm run build`、`cd server && npm test`
  （13 个 spec / 180 项断言）全部通过。
- **三档视口真实渲染核验**（Edge headless + CDP 驱动，375 / 768 / 1280 × 工作台 / 合同台账 / 采购发起 / 合同起草
  = 12 个组合，36 项断言全通过）：

  - `<768`：侧栏为抽屉（`hasDrawer=true, hasSider=false`）；`≥768`：固定侧栏 220px、无抽屉；
  - 筛选表单列数随断点：375 → 2 列、768 → 3 列、1280 → 4 列；
  - 42 列合同台账可横向滚动；
  - 抽屉交互单独核验（4/4）：初始关闭 → 点 ☰ 打开（220px、含菜单与 Logo、无折叠按钮）→

- 顺带修复：**合同台账列宽单位错用**（见下）。

## 1. 目标与断点约定

- 采用 **Ant Design 默认断点**：`xs <576 · sm ≥576 · md ≥768 · lg ≥992 · xl ≥1200`。
- 验收目标：**≥768 平板完全可用；≥375 手机可读可操作**（查看 / 录入 / 审批 / 导出等关键流程能走通）。
- **不做**：36 列台账等大宽表的卡片化（ROI 极低，见 §5）。

## 2. 改造分层与落点

### L1 · 断点基建（新增）

- 新增 `web/src/hooks/useResponsive.ts`：封装 `Grid.useBreakpoint()`，导出
  `{ isMobile(<768), isTablet, isDesktop }`，作为**全站断点唯一来源**（避免各处用 `window.innerWidth`）。
- 扩展 [web/src/index.css](../web/src/index.css)：把现有唯一媒体查询扩展为**全局断点样式**
  （窄屏 `.page-card` padding、表格/弹窗兜底规则）。

### L2 · 布局层（核心）

- [web/src/layouts/BasicLayout.tsx](../web/src/layouts/BasicLayout.tsx)：由 `useResponsive` 驱动——
  `isMobile` 时**侧栏自动收起**（受控 `collapsed`）、Content `margin` 由 `16` → `8`。
- [web/src/components/Sider/index.tsx](../web/src/components/Sider/index.tsx)：新增 **Drawer 模式**——
  窄屏下侧栏改为 `<Drawer placement="left">` 覆盖式，**选中菜单后自动关闭**。
- Header 窄屏精简：`ProjectSwitch` 限宽、用户菜单只留头像。

### L3 · 表格层（核心，策略分级）

| 表格类型 | 代表 | 策略 |
|---|---|---|
| 普通列表（10~15 列） | 采购六模块 [ModuleListPage.tsx](../web/src/components/procurement/ModuleListPage.tsx) | ≤md：**关键列 `fixed: 'left'` + 横向滚动**；可再提供"卡片列表"降级 |
| 大宽表（**36 列**等） | 合同台账 [Ledger.tsx](../web/src/pages/Ledger.tsx)、[Projects.tsx](../web/src/pages/Projects.tsx)（1950）、日报 | **不做卡片化**——保留横向滚动 + **冻结前 2 列** |

- 统一给各 `<Table>` 补 `scroll={{ x }}` 与 `fixed` 列；`ModuleListPage` 的筛选区（`PER_ROW=4`）改按断点自适应列数。

### L4 · 弹窗 / 表单层

- 65 处 `<Modal>` 统一改**响应式宽度**：`width={{ xs: '100%', md: 1000 }}`（或 `style={{ maxWidth: '94vw' }}` + `centered`）；
  重点：[PreviewPublishModal.tsx](../web/src/components/PreviewPublishModal.tsx)、
  [TaskViewModal.tsx](../web/src/components/procurement/TaskViewModal.tsx)。
- 表单：把 36 处**固定 `span`** 的 `<Col span={n}>` 改为 **`xs={24} md={n}`**（大表单窄屏单列）。

### L5 · 组件层

- [RichTextEditor.tsx](../web/src/components/RichTextEditor.tsx)：工具栏窄屏**折叠为「更多」下拉**。
- [Uploader.tsx](../web/src/components/Uploader.tsx)、ECharts 容器（Dashboard / Reports）：确保宽度随容器 resize。
- 预览/文档区固定 `padding:24` → 窄屏 `12`。

## 3. 统一规范（改造后同步进 [DESIGN.md](../DESIGN.md)）

> **现状（2026-10-15）**：本节四条硬性约定的**权威版本已迁到 [DESIGN.md](../DESIGN.md) §10**
> （连同视觉 token 体系一起重写过）。此处只保留制定时的原文，便于对照"方案 ↔ 实现"。

1. 表单 `<Col>` **一律** `xs={24} md={n}`，**禁止固定 `span`**。
2. 表格**必须**声明 `scroll={{ x }}`；≤md **冻结关键列**。
3. 弹窗 `width` **必须**响应式，且 `centered`。
4. 侧栏 ≤md 走 **Drawer**；**布局断点唯一来源 = `useResponsive`**。

## 5. 风险与取舍

- **36 列台账不卡片化**（明示取舍）：列数过多，移动化收益低，保留横向滚动 + 冻结列。
- **回归面广**（改动 ~40+ 文件、65 个 Modal）：前端**无自动化测试** → 必须**逐层灰度**，
  每页改完用 DevTools **三档断点（375 / 768 / 1280）**人工核。
- 与 [docs/05 §13](05-四域扩展可行性评估.md) 的"**不做全站响应式改造**"结论**部分相悖**：
  本方案是"**全站布局响应式 + 表格降级而非卡片化**"，为业务方上调目标后的版本，请知悉。
