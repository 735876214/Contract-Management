# 项目整体说明（Project Overview）

> 面向新成员/干系人：**这是什么系统、给谁用、能做什么、怎么跑起来**。
> 技术细节见 [architecture.md](architecture.md)；操作说明见 [user-guide.md](user-guide.md)。

## 1. 一句话

**企业合同管理系统（CMS）**：面向工程 / 采购型企业的**合同全生命周期管理系统**，
把「项目 → 供应商/分包商 → 采购 → 合同 → 日报 → 结算付款 → 发票 → 台账 → 还款」全链路
收在一个平台内，并以字典驱动、多项目隔离，覆盖从起草到归档的完整流程。

## 2. 解决的问题

工程/采购型企业的合同管理普遍痛点：

- 合同、结算、付款、发票散落在 Excel 与多个系统，**对不上账**；
- 采购流程（公告、比价、成交）靠线下推进，**无留痕、无门禁**；
- 台账口径靠人肉汇总，**滞后且易错**；
- 多项目并行时数据混在一起，**缺乏隔离**；
- 审批、提醒靠口头/微信，**易漏**。

本系统用统一的字典、编号规则、台账视图与工作流门禁解决上述问题。

## 3. 用户与角色

| 角色 | 典型职责 | 权限载体 |
|---|---|---|
| 系统管理员 | 用户/角色/权限/参数/字典/日志 | `isSuperAdmin`（绕过权限）+ `system:*` |
| 项目管理员 | 单项目全流程管理 | `ProjectMember.roleCode = ADMIN` |
| 业务专员（采购/合同/结算） | 对应模块 view/edit | 角色绑定的权限码 `module:action` |
| 只读用户 | 查看台账/报表 | `*:view` |

> 组织维度**不使用独立部门表**：数据权限由「项目 + 项目内角色」承担。

## 4. 功能地图（按菜单组织）

### 4.1 采购管理（本项目特色）

三种采购类型驱动不同阶段链（详见 [user-guide.md §采购](user-guide.md)）：

- **单项采购 SINGLE**：总清单 →（≥100 万需采前会）→ 采购公告 → 采购文件 → 成交报告 → 价格对比表 → 生成合同
- **框架协议采购 FRAMEWORK**：总清单 → 价格对比表 → 框架协议事前说明 → 生成合同
- **紧急采购 EMERGENCY**：总清单 → 生成合同

阶段间有**顺序门禁**（前一阶段未完成，后续锁定），并支持**三处驳回**（成交报告退回、合同签章驳回、结算驳回）。
采购完成可自动推送草稿合同到「合同起草」。

### 4.2 合同管理

- 合同起草（物料池 + 合同清单两个 Tab）、合同查询、**合同台账**（36 列综合视图）、合同物资清单
- 合同模板库（富文本 + 变量占位符 + 版本回滚）、条款库、采购模板

### 4.3 日报与收领

总日报（35+ 字段，物资种类按材料类别联动）、收领单（供应/领用单位多类型）、资产台账。

### 4.4 结算及付款

结算单、结算台账、资金费用台账（保理费用 / 逾期利息，DAYS360 计息）、付款管理。

### 4.5 其他

发票管理（收票登记/开票申请/查重/二维码识别）、还款协议、消息中心、统计报表（工作台 + ECharts 看板）。

### 4.6 基础信息与系统管理

项目管理、供应商库、分包商库、物资基础库、合同模板、采购模板、合同条款；
用户、角色、系统参数、字典、日志。

## 5. 核心设计原则（贯穿全系统的"脾气"）

1. **字典驱动**：所有下拉、选项、标签颜色来自 `dict_type`/`dict_item`；业务表存字典项编码。
   字典项被引用不可删、只能停用。
2. **供应商单一数据源**：合同只存 `supplierId`，供应商信息实时关联、后台账自动更新。
3. **多项目隔离**：业务数据带 `projectId`，请求头 `x-project-id` 传递当前项目。
   供应商可配置全局共享或项目隔离（系统参数 `supplier.share.scope`）。
4. **编号唯一性可配置**：合同编号默认全局唯一，可切「项目内唯一」；还款协议编号默认项目内唯一。
5. **合规性自动计算**：如「未签合同先进场」「招标/定标/签订时间倒挂」「时间数据不完整」由服务层计算，不落库。
6. **全链路留痕**：操作日志（含变更前后快照）、登录日志、合同变更日志。
7. **导入导出全覆盖**：主要业务支持 Excel 模板下载/导入/导出；导入**全成功或全失败**，超 1000 行异步执行。

## 6. 技术形态与部署

- **形态**：前后端分离的 Web 系统。后端 REST API（`/api`），前端单页应用。
- **部署**：**单容器**（内部 nginx 托管前端并把 `/api` 反代到同容器后端）+ 独立 PostgreSQL 服务，
  由 `docker-compose.yml` 一键拉起，对外单端口（默认 `9080`）。
- **发布**：push `main` → GitHub Actions 构建 `ghcr.io/735876214/cms-single` → NAS `docker compose pull`。
- **快速体验**：`docker compose -f docker-compose.dev.yml up`（源码热重载，前端 :5173）。
