# 01 · 需求确认摘要

> **文档状态**：本文件源自需求确认阶段，**2026-10 已按实现校准**。
> 早期版本的「15 个模块」清单已过期（现为 22 个后端模块）；「部门管理」**已移除**。
> 实现细节以 [architecture.md](architecture.md)、[02-数据库ER设计.md](02-数据库ER设计.md) 与代码为准。

## 1. 目标与范围

面向工程/采购型企业的合同全生命周期管理系统，覆盖
「项目 → 供应商/分包商 → 采购工作流 → 合同 → 日报/收领单 → 结算付款 → 发票 → 台账 → 还款协议」主链路，
并配套模板、通知、看板与系统管理能力。

## 2. 模块清单（当前实现：22 个后端模块）

| # | 模块 | 关键能力 |
|---|------|----------|
| 1 | 认证 auth | JWT 登录、RBAC 权限守卫、找回/修改密码 |

> 早期清单中的「部门管理」「付款计划/付款申请」「资审报告」**均已移除或重构**：
> - **部门**：无独立部门表，组织维度由「项目 + 项目内角色」承担；
> - **付款**：仅保留 `PaymentRecord`（付款执行与台账合一）；
> - **资审报告**：已从采购阶段链移除。

## 3. 关键业务规则确认

1. **字典驱动**：所有下拉/单选/复选/标签颜色来自 `dict_type` / `dict_item`；字典项被引用不可删除只可停用；
   默认全局共享，可通过字典 `scope`（GLOBAL/PROJECT）区分。
2. **供应商单一数据源**：合同不冗余法人/授权人/联系人/银行信息，仅存 `supplierId`；合同表单自动带出并**只读**；
   台账实时关联，供应商变更后台账自动更新。
3. **项目隔离**：合同、日报、结算、付款、发票、清单、收领单、采购任务等均带 `projectId`，
   前端用请求头 `x-project-id` 传递当前项目；供应商库可配置全局共享（默认）；
   例外：字典全局、资金费用按 `contractId` 归属。
4. **编号唯一性**：合同编号默认**全局唯一**，可通过系统参数切换为「项目内唯一」；还款协议编号默认项目内唯一。
   前端实时查重 + 后端保存校验。
5. **合规性问题**（不落库，服务层计算）：
   - 执行合同（采购执行/租赁执行）：进场日期 ≥ 签订日期 → 无问题；早于 → 未签合同先进场。
   - 非执行合同：依次比较开始招标时间 → 定标时间 → 签订时间，命中即标记；关键时间缺失 → 时间数据不完整。
6. **合同台账指标**：开累结算/审定结算/开累进项税/开累发票/开累付款、应付款、应付未付、100% 欠款、两个占比、
   审减额、按年汇总，均由服务层汇总计算（批量查询避免 N+1）。
7. **合同模板生成向导**：是否框架协议 → 是否补充协议 → 模板分类 → 具体模板，四步筛选。
8. **采购工作流**（新增，详见 [architecture.md §7](architecture.md)）：三种采购类型驱动不同阶段链，
   阶段顺序门禁；支持三处驳回（成交报告退回、合同签章驳回、结算驳回）；完成后自动推送草稿合同。
9. **删除约束**：字典项被引用、供应商被合同引用、物资主数据被清单引用时禁止删除，仅可停用；
   停用后新数据不可选，历史数据正常展示。

## 4. 非功能要求

- 统一返回 `{ code, data, message, timestamp }`；全局异常过滤与参数校验（`ValidationPipe` whitelist）。
- 操作日志（含变更前后快照）/ 登录日志留痕。
- 数据权限：项目隔离 + 项目内角色。
- 后端字典缓存，变更即刷新；前端字典按需加载并缓存。
- 台账查询批量聚合，避免 N+1。
- 导入「全成功或全失败」（两阶段校验 + 事务），超 1000 行自动转异步任务。
- 响应式布局（Grid / Table 横向滚动 / 栅格表单）。
