## 0. 结论摘要

- **20 个维度全部查过**，每一维都有命令输出/代码证据支撑，不是「看着没问题」。
- **本轮新增真缺陷：2 处**（都属 P3 稳健性，非安全漏洞）：
  1. `receipt-order.service.ts` 两处裸写 `status: 'SAVED'` → 违反「状态码写常量」铁律，已抽 `RECEIPT_STATUS`。
  2. `AiQuota.hits` 只在「本人再次调用」时才清理自己那条 → 调用过 AI 却不再回来的用户条目永久滞留，
     单实例常驻进程下只增不减（慢速内存泄漏），已加阈值触发的过期条目回收 + 回归用例。
- **一处曾疑为 P2 的问题被证伪并撤回**：AI 登记里 `supplier.findFirst({ where: { name } })` 未带
  `projectId`。查 `prisma/schema.prisma`：`Supplier` 的 `name` 是**全局唯一**、`projectId` 可空
  （`// 全局共享时为空`），供应商基础库本就是跨项目主数据 → 不带 `projectId` 是设计如此，不是越权。
- **验收**：`server` / `web` 两个 build 通过、`npm test` 全绿、`test:int` 53/53（新建空库跑全部 33 个迁移）。

## 1. 审计方法

1. **静态扫描**：自定义 node 脚本扫「白名单里的危险字段」「权限装饰器 ↔ 权限码对照」「裸写状态串」
   「`findFirst/findUnique` 是否带 `projectId`」「`toISOString().slice` 时区截断」「空 catch」
   「`$transaction` 覆盖」「导出公式注入」「`dangerouslySetInnerHTML`」。
2. **逐个读码确认**：每个命中都读到上下文 + 相邻守卫，区分「缺陷」与「有兜底/设计如此」。
3. **跑起来验**：`prisma migrate deploy` 到全新空库、`prisma migrate diff` 复核 schema↔迁移零漂移、
   `npm run test:int` 跑真库。
4. 环境注意：容器内 `NODE_ENV=production` 会让 npm 漏装 devDependencies（需 `--include=dev`）；
   git 走 HTTP 代理必须 `http.version=HTTP/1.1`。
