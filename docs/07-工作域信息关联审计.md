# 07 · 工作域信息关联审计

> **文档状态**：2026-10-13 基于 `schema.prisma` 与 service 层实测审计。**结论：主链路完整，
> 但存在 27 处悬空引用（无外键）与若干"仅靠字符串/间接键"的弱关联**——构成关联中断与不清晰。
> 本文只做审计与建议，**未改动代码**；基准 main @ `0755e7c`。

## 0. 摘要

| 维度 | 结论 |
|---|---|
| 主链路（合同 → 结算 → 付款 → 发票 → 台账） | ✅ **外键完整** |
| 悬空引用（有 `xxxId` 但无 `@relation`） | ⚠️ **27 处**，涉及 15 个模型 |
| 其中真实缺口（应关联未关联） | ⚠️ 8 类 |
| 其中指向已删除结构的**死字段** | ❌ `PaymentRecord.applyId`（指向已移除的 `PaymentApply`） |
| 仅靠字符串/间接键的弱关联 | ⚠️ 收领单→日报（`receiptNo` 文本）、采购任务↔合同（双写）等 |
| 核销（发票 ↔ 付款） | ❌ **缺失**（全库无 `Verification`） |

> 附：实际 **50 个 model**（此前文档写作 45，已一并更正）。

## 1. 审计方法

1. 解析 `server/prisma/schema.prisma`：对每个 model 收集
   ① 形如 `xxxId` 的标量字段；② `@relation(fields: [...])` 承载的外键字段。
   **`xxxId` 不在 ② 中 = 悬空引用**（无引用完整性）。
2. 对每个悬空字段，grep `server/src` 判断是**在用**（弱关联）还是**未用**（死字段）。
3. 人工核对跨域链路的显式外键是否存在。

> 检测脚本见 [附录](#附录--悬空引用检测脚本)。

## 2. 关联健康的域（有 FK，引用完整）

- 组织权限：`User ↔ UserRole ↔ Role ↔ RolePermission ↔ Permission`；
- 项目：`Project ↔ ProjectMember`（`@@unique([projectId, userId])`）；
- 合同：`Contract ↔ Project/Supplier/ContractExt/ContractAttachment/ContractChangeLog/ContractMaterial`；
- 结算付款发票：`Contract ↔ Settlement/SettlementLedger/PaymentRecord/Invoice`（均 `contractId` FK）；
- 还款：`RepaymentAgreement ↔ RepaymentDetail`（Cascade）；
- 收领：`ReceiptOrder ↔ ReceiptOrderDetail`（Cascade）；
- 采购：`ProcurementTask ↔ 各阶段子表`（`taskId @unique`，Cascade）；
- 物资：`MaterialBase ↔ ContractMaterial`（`onDelete: Restrict`）；
- 字典：`DictType ↔ DictItem`（`typeCode`）。

## 3. 关联中断：27 处悬空引用

### 3.1 A 类 — 应关联但未建 FK（真实缺口）

| 字段 | 语义 | 现状 / 风险 |
|---|---|---|
| `Contract.templateId` | 关联合同模板 | **在用**（`contract.service` 校验/导出都读它），但无 FK → 模板删除后合同指向空 |
| `Contract.technicalClauseId` / `qualityClauseId` / `paymentClauseId` / `acceptanceClauseId` | 四个条款 | **在用**（导出时取条款文本），无 FK |
| `ContractTemplate.parentId` | 模板版本链（上一版本） | 无自关联 → 版本链无完整性保证 |
| `ProcurementTotalItem.materialBaseId` | 引用物资基础库 | **与 `ContractMaterial`（有 FK + `Restrict`）口径不一致**，可指向不存在物资 |
| `Subcontractor.subcontractId` | 关联分包合同（与合同互锁） | **在用**（`receipt-order.service` 读），无 FK |
| `AssetLedger.receiptOrderId` / `receiptDetailId` | 来源收领单 | service **手工** `delete/create`，无级联 → 收领单删除后资产台账可能残留 |
| `ReceiptOrderDetail.materialId` | 引用物资基础库 | 无 FK |
| `ReceiptOrder.subcontractorId` | 关联分包商 | 无 FK |

### 3.2 B 类 — 指向已删除结构的死字段（明确中断）

- **`PaymentRecord.applyId`**：指向**已移除的 `PaymentApply`**（付款计划/申请模块已重构为单表 `PaymentRecord`）。
  现仅出现在 `payment.service` 的字段白名单里，**既不写入也不读取** → 死字段。
- 连带确认：**"核销 / verification" 全库 0 命中** → `docs/03` 中的
  `/payments/plans`、`/payments/applies`、`/payments/verifications` **均已不存在**；
  **发票 ↔ 付款之间没有核销关联**，"三单匹配"无落点。

### 3.3 C 类 — 有意弱关联（设计取舍，需知晓）

| 字段 | 说明 |
|---|---|
| `Supplier.projectId` · `Subcontractor.projectId` · `ContractTemplate.projectId` | `null` = **全局共享**，故意不做 FK（受系统参数 `supplier.share.scope` 控制） |
| `Project.managerId` · `ContractChangeLog.operatorId` | 操作人/负责人，弱关联 |
| `Notification.bizId/projectId` · `OperationLog.bizId/projectId` · `ImportTask.projectId/userId` | 通用表按 `bizType + bizId` 弱关联，**合理** |
| `ReceiptOrder.receivingUnitId` | 领用单位是**多态**（分包商 / 本项目 / 其他项目），故不做单一 FK |

## 4. 关联不清晰：同一关系多表达 / 仅靠间接键

| # | 问题 | 证据 |
|---|---|---|
| 1 | **采购任务 ↔ 合同"双写"** | `Contract.taskId`（有 FK）**与** `ProcurementTask.contractId`（**悬空**）表示同一关系 → 两处可能不一致 |
| 2 | **收领单 → 日报靠字符串** | `dailyReport.deleteMany({ where: { projectId, receiptNo: order.orderNo } })` —— 用 **`receiptNo` 文本**关联与去重，**编号变更/不规范即断链** |
| 3 | **收领单 → 资产台账靠非 FK** | `assetLedger.deleteMany({ where: { receiptOrderId } })` 手工维护 |
| 4 | **结算单 ↔ 结算台账无显式关联** | `SettlementLedger` 无 `settlementId`，只靠 `contractId + settleMonth` |
| 5 | **发票 ↔ 结算/付款无核销** | `Invoice` 仅 `contractId`；无核销模型（§3.2） |
| 6 | **资金费用 ↔ 结算/付款无关联** | `FactoringCost` / `OverdueInterest` 只挂 `contractId` |
| 7 | **收领单 ↔ 结算/付款/发票无 FK** | 仅经 `contractId` / `projectId` 间接 |
| 8 | **合同类型双字段** | `typeCode`(dict: contract_type) 与 `contractType`(enum 五态) 语义重叠 |

```
项目 ──FK── 供应商 ──FK── 合同 ──FK── 结算单 ──FK── 付款 ──?── 发票        ✅ 主链完整
                            │
                            ├─FK─ 采购任务 (Contract.taskId)                ✅

                            ├─FK─ 收领单

                            │        └╌非 FK╌→ 资产台账                     ⚠️ 手工关联

发票 ─╌✗ 核销 ╌─ 付款                                                    ❌ 缺失
```

## 6. 修复建议（按优先级）

1. **清死字段（风险最低，先做）**：删除 `PaymentRecord.applyId`；同步更新 `docs/03-API接口清单.md`（已登记待重写）。
2. **补关键 FK**：`Contract.templateId`、4 个 `*ClauseId`、`ContractTemplate.parentId`、
   `ProcurementTotalItem.materialBaseId`、`Subcontractor.subcontractId`、`AssetLedger.receiptOrderId`、
   `ReceiptOrderDetail.materialId`、`ReceiptOrder.subcontractorId`；
   按语义选 `Cascade`（单据从属）/ `Restrict`（主数据）/ `SetNull`（可选从属）。
3. **显式化弱关联**：收领单→日报 增加 `DailyReport.receiptOrderId`（替代 `receiptNo` 文本匹配）；
   `SettlementLedger` 增加 `settlementId`（或明确声明"不强关联"并在文档写明）。
4. **去重**：采购任务 ↔ 合同保留 `Contract.taskId` 一条，移除/改为派生 `ProcurementTask.contractId`。
5. **核销（按需）**：若需三单匹配，补 `Verification` 模型；否则在文档中**明确"不做核销"**。
6. **收紧口径**：`ProcurementTotalItem.materialBaseId` 与 `ContractMaterial.materialBaseId` 的引用策略统一。
7. **防回归**：见 §7。

## 7. 防回归建议

新增一个 **schema 悬空引用校验测试**（纯解析 `schema.prisma`，**无 DB 依赖**，可进 `cd server && pnpm test`）：

- 断言：模型内形如 `xxxId` 的标量字段**必须**出现在某 `@relation(fields: [...])` 中；
- 维护一个**白名单**豁免 C 类有意弱关联（`Supplier.projectId`、`Notification.bizId` …）；
- 新增悬空字段而无白名单登记时测试失败 → 把"关联中断"变成 CI 可捕获。

## 附录 · 悬空引用检测脚本

```python
# 解析 schema.prisma，列出「有 xxxId 字段但无 @relation 外键」的字段
import re
p = "server/prisma/schema.prisma"
models, cur = {}, None
for ln in open(p, encoding="utf-8").read().splitlines():
    m = re.match(r"model\s+(\w+)\s*\{", ln)
    if m:
        cur = m.group(1); models[cur] = {"fields": [], "rel": set()}; continue
    if cur and re.match(r"\}", ln):
        cur = None; continue
    if not cur: continue
    s = ln.strip()
    if not s or s.startswith(("//", "@@")): continue
    models[cur]["fields"].append(s)
    fm = re.search(r"@relation\([^)]*fields:\s*\[([^\]]*)\]", ln)
    if fm:
        models[cur]["rel"] |= {f.strip() for f in fm.group(1).split(",")}
for name, d in models.items():
    dg = [re.match(r"^(\w+)\s", s).group(1) for s in d["fields"]
          if re.match(r"^(\w+)\s+(String|Int)\??(\s|$)", s)
          and re.match(r"^(\w+)\s", s).group(1).endswith("Id")
          and re.match(r"^(\w+)\s", s).group(1) != "id"
          and re.match(r"^(\w+)\s", s).group(1) not in d["rel"]]
    if dg:
        print(f"{name}: {', '.join(sorted(set(dg)))}")
```

> 实测输出：**27 个悬空字段，涉及 15 个模型**（见 §3）。
