# 02 · 数据库 ER 设计

> **文档状态**：2026-10 依据 `server/prisma/schema.prisma`（**52 个 model**，PostgreSQL）全面校准。
> 早期版本中的「部门（Dept）」「付款计划（PaymentPlan）」「付款申请（PaymentApply）」等表**已不存在**，
> 请以 `schema.prisma` 与本文为准。
>
> 通用约定：
> - 主键统一 `id String @id @default(cuid())`；时间 `createdAt` / `updatedAt`。
> - 金额 `Decimal @db.Decimal(18,2)`（单价/数量按需更高精度，如 4 位小数）。
> - **乐观锁**：多数业务表含 `version Int @default(0)`，更新时校验。
> - **项目隔离**：业务表含 `projectId`；`Supplier` / `Subcontractor` / `ContractTemplate` 的 `projectId` 可空
>   （为空表示**全局共享**）。
> - **停用/软删**：用 `status`（`Int` 1/0，或业务字符串如 `DRAFT`/`EDITING`），**无统一 `deletedAt`**。
> - **字典驱动**：字典关联字段一律存**字典项编码字符串**，由字典服务校验，不使用数据库枚举。
> - **全库零 DB enum**（2026-10-16 起）。此前唯一的 `ContractType` 是 `typeCode` 的派生副本、且全仓无读者，
>   已连同列一起删除——五态由纯函数 `deriveContractType()` 推导（见 CLAUDE.md 铁律 4）。

## 一、组织与权限域

```
User >──< Role            [UserRole 多对多]
Role >──< Permission      [RolePermission 多对多]
User 1 ──< ProjectMember ──> Project
User 1 ──< OperationLog / LoginLog
```

- `User`：id, **username(唯一)**, password(bcrypt), realName, phone?, email?, status(1启用/0停用),
  isSuperAdmin, lastLoginAt?, createdAt, updatedAt
  > ⚠️ **无 `deptId`**：部门管理已移除，数据权限维度只有「项目 + 项目内角色」。
- `Role`：id, code(唯一), name, remark?, status
- `Permission`：id, **code(唯一，如 `contract:create`)**, name, module
- `UserRole` / `RolePermission`：关联表，各自 `@@unique`，`onDelete: Cascade`

## 二、项目域

- `Project`：id, **code(唯一)**, name, nameAbbr?, **codeAbbr(唯一，字母简称，用于合同编号第3段)**,
  undertaker?(承接单位), selfContractAmount?(项目自施合同额/万元), industryType?(dict: industry_type),
  **provinceCity / siteLocation / projectAddress / materialOrigin**（项目所在省市/工程地点/项目地址/物资产地）,
  status?(dict: project_status), description?, startDate?, endDate?, managerId?, packageLeader?（项目包保领导）, projectManager?（项目经理）, version
- `ProjectMember`：id, projectId, userId, roleCode(默认 MEMBER，dict: project_member_role)，
  `@@unique([projectId, userId])`

> 四个「位置/属地」字段同时是采购模板的公共变量来源（`{{项目所在省市}}` 等）。

## 三、供应商 / 分包商域（独立主数据，不冗余进合同）

- `Supplier`：id, **name(唯一)**, legalPerson?, legalPhone?, contractAuthPerson?, contractAuthPhone?,
  contractAuthIdNo?, contactName?, contactPhone?, contactEmail?, bankName?, bankAccount?, address?,
  remark?, status?, **projectId?(空=全局共享)**, version
- `Subcontractor`（分包材料员授权委托书）：id, projectId?, subcontractorName, subcontractContent?,
  subcontractId?(关联分包合同，互锁), legalPerson?, authorizedPerson?, authorizedPersonIdNo?, projectName?,
  idCardFront? / idCardBack? / signatureScreenshot?, signedAuthFile?(签章版委托书),
  **status(EDITING 编辑中 / COMPLETED 已完成)**, createdBy?, version

## 四、合同域

```
Contract >── Supplier(supplierId?)
Contract 1 ── 1  ContractExt
Contract 1 ──< ContractAttachment / ContractChangeLog
Contract 1 ──< ContractMaterial / ContractMaterialPool / ContractDraftMaterial
Contract 自关联 parentContractId（补充协议链 SupplementChain）
Contract N ── 1 ProcurementTask(taskId)（一个采购任务可生成多个合同）
```

- `Contract`：id, projectId, **code**, name, typeCode?(dict: contract_type), **contractType?(enum 五态)**,
  subTypeCode?, supplierId?, signDate?, amount?, taxRate?, paymentMethodCode?, isFramework?, isSupplement?,
  parentContractId?, yearSeq?, codeAbbrUsed?, supplementSeq?, supplementTypeCode?, execStatus?,
  **status?**(合同流转 DRAFT 草稿中 / COMPLETED 已完成), templateId?, formData?(模板变量 JSON),
  materialDescription?, 四个条款 ID（technical/quality/payment/acceptanceClauseId）,
  签章字段（signedFilePath/Name/Date/Remark/At）, paymentMode?, monthlyRate?, graceDays?, interestCapRatio?,
  createdBy?, taskId?, **archivedAt? / archivedBy?**（单向归档，2026-10-18；归档后锁业务单据写操作）, version
- `ContractFulfillment`（履约节点，四域扩展按需项 2026-10-18）：projectId, contractId, name,
  planDate?, actualDate?, owner?, statusCode?(MILESTONE_STATUS：PENDING/DONE/SKIPPED，非字典驱动),
  remark?, version；**逾期 = 派生**（未完成且 planDate 已过，见 `common/utils/milestone.ts`），不落库
  - `@@unique([projectId, code])`；**全局唯一**由服务层按系统参数 `contract.code.unique.scope` 校验
- `ContractExt`（1:1，`contractId @unique`）：financeCode?(财务一体化编号), procurementSrc?, isDirectPurchase?,
  bidName?, currentPayRatio?, supplierCategory?, bidStartDate?, bidWinDate?, disclosureDate?, complaint?
- `ContractAttachment`：contractId, fileName, url, size?
- `ContractChangeLog`：contractId, field, fieldLabel?, beforeValue?, afterValue?, operatorId?, operator?

## 五、模板与条款域

- `ContractTemplate`：id, name, categoryCode?(dict), tags?, status, **version(从 1 递增)**, content(HTML, Text),
  pageSetup?(页面设置 JSON), **projectId?(空=全局)**, parentId?(上一版本), createdBy?
- `TemplateVariable`：templateId, varKey, varLabel?, sourceType(SUPPLIER/CONTRACT/MANUAL), defaultValue?
- `Clause`（条款库）：title, content(Text), categoryCode?, **type?(technical/quality/payment/acceptance)**, sortOrder, status

## 六、日报与物资域

- `DailyReport`（35+ 字段）：projectId, materialBaseId?(物资主数据来源), periodYear/Month?, entryDate?, exitDate?(出场日期，2026-10-18，只填不参与自动计算),
  contractId?, 物资属性（isAsset/isSafetyMaterial 来自物资基础库、assetSupervision、**department(文本)**、
  personnel、assetStatus、sourceCode、materialCategory、materialType、materialName、spec、unit）,
  数量（weighQty/deductQty/settleQty）、价格（priceBeforeTax/taxRate/priceAfterTax/amountBeforeTax/amountAfterTax）、
  供应（supplierId、receiveUnit、receiver）、其他（usePosition、isProxy、plateNo、receiptNo、
  incomePrice/incomeAmount、stdPrice/stdAmount）、version
  - `materialType` 通过字典 `extField1` 指向 `materialCategory` 编码实现**联动**
- `MaterialBase`（物资基础库，主数据）：name, spec, categoryLevel1/2(dict：`material_category` / `material_type`；
  2026-10-18 起按业务分类表同步，二级通过 `extField1` 挂到一级编码；创建/导入时服务端校验；
  同步仅在首次/版本升级时全量执行，之后只补缺失项、不覆盖字典管理里的手工维护), mdmCode?, dscCode?,
  unit(dict，创建后不可改), isAsset, isSafetyMaterial, status, version
  - `@@unique([name, spec])`（名称 + 规格组合唯一）
- `ContractMaterial`（合同物资清单实例行）：contractId, materialBaseId, unit, qty?, priceBeforeTax?,
  taxRatePct?, priceWithTax?, totalWithTax?, incomePrice/Total?, stdPrice/Total?, sortOrder
  - `@@unique([contractId, materialBaseId])`；`materialBase` 为 `onDelete: Restrict`
- `ContractMaterialPool`（起草物料池）/ `ContractDraftMaterial`（起草草稿清单）：结构类似，均 `@@unique([contractId, materialBaseId])`

## 七、结算 / 付款 / 发票域

- `Settlement`（结算单）：projectId, contractId?, code?, typeCode?(dict: settlement_type),
  amount?, deductAmount?, actualAmount?, settleDate?, statusCode?(dict), version
- `SettlementLedger`（结算台账行）：projectId, contractId?, settleMonth?(YYYY-MM),
  monthSettleAmount?, monthInvoiceAmount?, settleCount?, yearSettleAmount?, cumPurchaseAmount?,
  startSettleAmount?, monthActualPurchase?, factoringDiscount?, overdueInterest?, yearSettleIncome?,
  cumSettleIncome?, isOnAccount?(dict: yes_no)
  - `@@unique([projectId, contractId, settleMonth])`
- `PaymentRecord`（付款执行 + 付款台账**合一的单表**）：projectId, contractId?, applyId?, payMonth?(YYYY-MM),
  amount?, methodCode?, payDate?, receiptUrl?(银行回单), statusCode?, version
  > 早期文档的「付款计划 PaymentPlan」「付款申请 PaymentApply」**已移除**，仅保留付款记录表。
- `Invoice`：projectId, contractId?, goodsCategory?, settlePeriod?, invoiceCode?, **invoiceNo?**,
  typeCode?, invoiceDate?, issuer?, receiver?, amountBeforeTax?, taxRate?, amountWithTax?, receiveDate?,
  reviewStatus?, responsiblePerson?, financeTransferStatus?, imageUrl?, statusCode?, version
  - `@@unique([projectId, invoiceNo])`（项目内票号唯一）

## 八、还款协议域

- `RepaymentAgreement`：projectId, **code**, supplierId?, contractId?, material?, signDate?,
  settleAmount?, agreedDebtAmount?, paidBeforeSign?, paidAfterSign?, overdueUnpaid?, version
  - `@@unique([projectId, code])`（项目内唯一）
- `RepaymentDetail`：agreementId, period?(期数), amount?, dueDate?, remark?

## 九、资金费用台账域

- `FactoringCost`（保理费用）：contractId, seqNo, financingDate?, financingAmount?, actualReceipt?,
  financingInterest?, handlingFee?, **totalCost?(服务端自动=利息+手续费)**, settlementMonth?(YYYY-MM)
- `OverdueInterest`（逾期利息，**DAYS360**：`ROUND(计息金额 × 逾期天数 × 月利率 ÷ 30, 2)`）：
  contractId, settlementMonth, materialAmount?, paymentRatio?, payableAmount?(自动), payableDate?,
  overdueStartDate?(自动=应付款日期+宽限期+1天), paymentDate?, paymentAmount?, interestAmount?(自动),
  overdueDays?(自动), monthlyRate?, overdueInterest?(自动，含税), **waived**(谈判减免记 0),
  prevCumulative?, isSettlementPeriod, periodSeq, version

## 十、资产台账域

- `AssetLedger`：projectId, date?, sourceCode?(dict: asset_ledger_source), categoryL1Code?/categoryFocusCode?,
  name?, spec?, unit?, qty?, price?, totalAmount?(自动), supplierId?, receiveUnit?, responsible?,
  在用/闲置/报废/丢失数量与金额（inUseQty…lostAmount，金额自动）, turnoverCount?, originalPrice?/originalTotal?(原值固定),
  transferOutPrice?/transferOutAmount?, receiptOrderId?, **receiptDetailId?(防重唯一键)**, version
  - `@@unique([receiptDetailId])`（收领单自动入账防重）

## 十一、收领单域

- `ReceiptOrder`：projectId, **orderNo(自动生成)**, supplierId?/supplierName?(快照)/supplierType?,
  receivingUnitId?/Name?/Type?, subcontractId?/Name?, supplySubcontractId?/Name?, subcontractorId?,
  orderDate?, receiver?, materialContractId?/No?, **status(DRAFT/SAVED)**, pushedAt?, createdBy?, version
  - `@@unique([projectId, orderNo])`；与 Contract 有三条命名关系（物资合同 / 分包 / 供应分包）
- `ReceiptOrderDetail`：orderId, materialId?, categoryLevel1/2?, materialName?, specModel?, unit?,
  contractQty?, deliveryQty?, receivedQty?, priceBeforeTax?, taxRate?, priceWithTax?(自动), totalPrice?(自动),
  usagePart?, brand?, isAgentPurchase?(dict), sortOrder

## 十二、采购工作流域（12 个 model）

```
ProcurementTask 1 ──< ProcurementTotalItem
ProcurementTask 1 ── 1 FrameworkExplanation / PreMeetingMinutes / ProcurementNotice
                        / ProcurementDocument / ProcurementResultReport / ProcurementPriceCompare
ProcurementTask 1 ──< ProcurementBidder ──< ProcurementEvaluation
ProcurementTask 1 ──< Contract（TaskContracts，一任务多合同）
ProcurementTemplate（项目 × 模块类型，各一份）
InspectionReport（考察报告，独立模块）
```

- `ProcurementTask`：projectId, **taskNo(PROC-YYYYMMDD-XXX)**, type(FRAMEWORK/SINGLE/EMERGENCY),
  content, purpose?, **status**(见 `TASK_STATUSES`), **stage(已发布阶段序号)**, preMeetingRequired,
  totalListId?, procurementCategory?(物资/租赁), techQuality?/acceptanceMethod?/paymentMethod?(富文本), version
  - `@@unique([projectId, taskNo])`
  - ⚠️ **与合同的关系只由 `Contract.taskId` 一条表达**（原先双写的 `contractId` 字段已于 2026-10-14 移除）。
- `ProcurementTotalItem`（总采购清单明细）：taskId, materialBaseId, materialName, spec, unit, qty?,
  incomePrice?/stdCost?/marketPrice?/infoPrice?/planPrice?(控制价), sortOrder
- 各阶段子表均 `taskId @unique`（一任务一份），字段见 `schema.prisma`：
  `FrameworkExplanation`（框架协议事前说明）、`PreMeetingMinutes`（采前会，仅 SINGLE 且 ≥100万）、
  `ProcurementNotice`（公告，仅 SINGLE）、`ProcurementDocument`（采购文件）、
  `ProcurementResultReport`（成交报告）、`ProcurementPriceCompare`（价格对比表）
- `ProcurementTemplate`：projectId, moduleType, templateName, content(HTML), variables?
  - `@@unique([projectId, moduleType])`
- **招标域结构化（2026-10-19）**：`ProcurementBidder`（投标/响应单位，单位一行、两轮报价各两列）
  `@@unique([taskId, bidderName])`；`ProcurementEvaluation`（评标记录：评委/得分/排名/结论，挂 bidder，Cascade）。
  与 `ProcurementResultReport.suppliers/candidates`（JSON 快照）**双写**，导入时同一事务内同步；
  定标（勾选候选人）= `status → WON` + 写 `finalPreTaxTotal`，生成合同的单位与金额取自这些行。
  ⚠️ 采购域半结构化字段（事前说明 5 列 / 采前会 4 列 / 公告联系人 2 列 / 成交报告 2 列 / 考察照片）
  已由 TEXT 存 JSON 字符串改为 **PG `jsonb`**（迁移 `20261109000000_semi_structured_jsonb`，
  2026-10-18）；Prisma 侧为 `Json`，服务端 `parseJsonArray` 同时兼容数组与历史 JSON 字符串。
- `InspectionReport`（考察报告，独立）：projectId, unitName, inspectionTime?, inspectionPlace?,
  inspectors?, content?, conclusion?, photos?(jsonb), publishedAt?

> 采购阶段链与状态由服务层 `constants/procurementFlow.ts` 推导，**不落库为独立字段**。

## 十三、字典与系统参数

- `DictType`：code(唯一), name, remark?, sort, status, isSystem, **scope(GLOBAL/PROJECT)**
- `DictItem`：typeCode, itemCode, itemName, sortOrder, status(1/0), color?, remark?,
  **extField1**(扩展，如 material_type → material_category 联动)
  - `@@unique([typeCode, itemCode])`
- `SysParam`：key(唯一), value?, remark?
  - 常见 key：`multi.project.enabled`、`supplier.share.scope`、`contract.code.*`、
    `ledger.columns.config`、`finance.overdue.*`、`repayment.code.prefix`

## 十四、通知与日志

- `Notification`：userId?, title, content?, type(默认 SYSTEM), bizType?, bizId?, projectId?, isRead
- `OperationLog`（审计增强）：userId?, username?, module?, action?, method?, url?, params?(Text), ip?,
  beforeData?/afterData?(变更前后快照), result?(SUCCESS/FAIL), message?, duration?, bizType?/bizId?/projectId?,
  导入专项（importFile/importRows/successCount/failCount/errorFileUrl）
- `LoginLog`：userId?, username?, ip?, userAgent?, result?
- `ImportTask`（异步导入）：module, moduleName?, fileName?, totalRows, processedRows, successCount,
  failCount, **status(PENDING/RUNNING/SUCCESS/FAILED)**, errorFileUrl?, projectId?, userId?, startedAt?/finishedAt?
- `ArchiveLog`（数据归档）：table, fromDate?, toDate?, rows, filePath?, createdBy?

## 十五、合同台账（不建表）

`ContractLedger` 为**服务层聚合视图**：以 `Contract` 为主表，批量 join `Supplier` / `ContractExt`，
聚合 `SettlementLedger` / `Invoice` / `PaymentRecord` / `DailyReport` 的汇总值，
再计算**合规性问题**与各项占比（详见 [architecture.md §8](architecture.md)）。列显隐存 `sys_param: ledger.columns.config`。

## 附：唯一约束与删除策略速查

| 约束 | 表 |
|---|---|
| `@@unique([projectId, code])` | Contract、RepaymentAgreement |
| `@@unique([projectId, invoiceNo])` | Invoice |
| `@@unique([projectId, orderNo])` | ReceiptOrder |
| `@@unique([projectId, taskNo])` | ProcurementTask |
| `@@unique([projectId, contractId, settleMonth])` | SettlementLedger |
| `@@unique([projectId, moduleType])` | ProcurementTemplate |
| `@@unique([taskId, bidderName])` | ProcurementBidder（**不能写成 `(taskId, supplierId, round)`**：`supplierId` 可空，PG 允许多个 NULL，等于约束不存在） |
| `@@unique([contractId, materialBaseId])` | ContractMaterial / Pool / DraftMaterial |
| `@@unique([name, spec])` | MaterialBase |
| `@@unique([receiptDetailId])` | AssetLedger |
| `@unique` 单列 | Supplier.name、User.username、Role.code、Permission.code、DictType.code、SysParam.key、ContractExt.contractId、各采购子表.taskId |
| `@@unique([projectId, userId])` | ProjectMember |

- **删除策略**：`Project` 关联的业务子表多为 `onDelete: Cascade`；
  `ContractMaterial.materialBase` 为 `onDelete: Restrict`（主数据被引用不可删）；
  字典项、供应商被引用时**只可停用**（服务层校验，非数据库约束）。
