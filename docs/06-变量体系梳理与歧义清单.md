# 06 · 变量体系梳理与歧义清单

> **文档状态**：2026-10-13 基于代码实测梳理；**同日已完成修复**（见 §0.1 修复记录，实现口径以代码为准）。

## 0. 摘要

项目中"变量"有**三个不同所指**（§1）。核心是**两套并存的占位符体系**（采购模板 / 合同模板），
二者**来源、语法、替换规则均不同**，是结构性歧义的主要来源。此外发现 **8 项具体歧义/缺陷**，
其中 **「预计采购金额」单位不一致（万元 vs 元）** 为最高风险。

## 1. 本项目"变量"的三个所指

| 2 | **合同模板变量** | [server/src/modules/template/template.service.ts](../server/src/modules/template/template.service.ts) + 前端 [Clauses.tsx](../web/src/pages/Clauses.tsx) 的 `VARIABLE_GROUPS` | 后端 `template.service.generate()` 的 `values`（渲染在 `template-render.ts`） | `{{变量名}}`（**单一语法**，与采购体系一致） |

## 2. 采购模板变量体系

### 2.1 结构与规则

- **公共变量**（`PROCUREMENT_COMMON_VARS`，无前缀）：`项目名称`、`项目简称`、`承接单位`、
  `项目所在省市`、`工程地点`、`项目地址`（**6 个**）。
- **模块专属变量**（`PROCUREMENT_MODULE_VARS`，带「模块名-变量名」前缀区分重名）：
  按 7 个模块分组（INITIATE / PRE_MEETING / NOTICE / DOCUMENT / RESULT_REPORT / PRICE_COMPARE / FRAMEWORK）。
- **变量类型**：普通文本（HTML 转义）、`table: true`（表格变量，注入真实表格 HTML）、
  `html: true`（富文本变量，HTML 原样注入）。
- **定义处**用 `v()` / `h()` 声明；[RichTextEditor](../web/src/components/RichTextEditor.tsx) 的
  「插入变量」面板由 `getProcurementVariableGroups(moduleType)` 提供。
- **替换**：[`replaceProcurementVariables()`](../web/src/constants/procurementVariables.ts)
  —— 只替换 `{{key}}`；未提供值的**保留占位符**（便于预览发现缺失）。

### 2.2 面板归属（两套面板并存）

| 页面 | 使用的面板 |
|---|---|
| 采购模板页 [Procurement/Templates.tsx](../web/src/pages/Procurement/Templates.tsx) | `getProcurementVariableGroups()`（采购体系） |
| 合同模板页 [Templates.tsx](../web/src/pages/Templates.tsx) | `Clauses.VARIABLE_GROUPS`（合同体系） |

### 2.3 定义 ↔ 取值 对照（逐模块核对结果）

| 模块 | 定义的模块专属变量 | 取值表 `build*VariableValues` | 一致性 |
|---|---|---|---|
| INITIATE | 采购编号 / 采购内容 / 采购类型 | **无**（采购发起不产出 Word） | ❌ **定义了但永不替换** |
| PRE_MEETING | 采前会-采购清单 / 采前会-采购成本分析表 + 采购内容 / 预计采购金额 / 会议时间 / 主持人 / 参会人员 / 编写人 / 审核人 / 技术质量要求 / 验收标准 / 付款条件 | `buildPreMeetingVariableValues` | ✅ |
| NOTICE | 采购公告-采购清单 + 采购编号 / 采购时间 / 采购内容 / 技术质量标准 / 验收方式 / 付款方式 / 联系人1·2 / 联系电话1·2 | `buildNoticeVariableValues` | ✅（联系人由 `contactVariableValues` 生成 `联系人N/联系电话N`，一致） |
| DOCUMENT | 采购文件-采购清单 + 采购编号 / 采购内容 / 技术质量标准 / 验收方式 / 付款方式 / 采购时间 / 响应保证金 / 报价说明 | `buildDocumentVariableValues` | ✅ |
| RESULT_REPORT | 成交单位数量 / 采购开启时间 / 开启地点 / 评审小组成员 / 审核通过响应单位数量 / 参与响应单位数量 / 弃权响应单位数量 / 有效响应文件数量 / 预计采购金额 + 4 张表格变量 | `buildResultReportVariableValues` | ✅ |
| PRICE_COMPARE | 采购内容 / 计价方式 + 明细表 | `buildPriceCompareVariableValues` | ✅ |
| FRAMEWORK | 采购内容 + 询价情况 / 价格对比表 / 成本分析表 | `buildExplanationVariableValues` | ✅ |

> **公共变量 6 个在 6 个模块的取值表中均存在，一致。**

## 3. 合同模板变量体系

- **定义**：`ContractTemplate.variables`（`varKey` / `varLabel` / `sourceType: SUPPLIER|CONTRACT|MANUAL` /
  `defaultValue`），内置模板见 [server/prisma/templates/purchase-exec-contract.ts](../server/prisma/templates/purchase-exec-contract.ts)。
- **取值**：后端 `template.service.generate()` 组装 `values`（含 `项目名称`、**`物资产地`**、`合同额`、
  `供应商名称`、`公司名称/银行/法人/联系人` 等）。
- **占位符替换**（`generate()` → 纯函数 [`renderTemplate()`](../server/src/modules/template/template-render.ts)）：
  **只认双花括号** `{{变量名}}`（表格占位符 `{{物料编码清单}}` / `{{合同清单}}` 同为一类，值由 `buildMaterialTables()` 生成）。
  - 单花括号 `{变量名}` 与英文遗留 key（`{{MATERIAL_CODE_TABLE}}` / `{{CONTRACT_ITEM_TABLE}}`）的支持
    **已于 2026-10-14 移除**（当时定稿「只保留双花括号」，见 §0.1 #5）——理由：项目无存量业务数据、无需兼容，
    且单花括号替换会误伤富文本里的 `<style>.x{color:red}</style>`、并对已插入的表格 HTML 做二次替换。
  - 存量 4 份模板的内容由迁移 `20261018000000_canonicalize_template_placeholders` 统一为双花括号
    （改写前后同一模板生成的正文**逐字节相同**，见该迁移文件头）。
  - 未取到值的占位符**原样保留**在正文中，由 `pendingPlaceholders()` 记日志提醒；前端 `highlightPlaceholders()` 会高亮。

## 4. 环境变量

**代码实际读取**（`server/src`）：`JWT_SECRET`、`JWT_EXPIRES_IN`、`PORT`、`UPLOAD_DIR`、
`DEFAULT_ADMIN_USERNAME`、`DEFAULT_ADMIN_PASSWORD`（共 6 个）。

**声明处**：[server/.env.example](../server/.env.example) 含 `DATABASE_URL/JWT_SECRET/JWT_EXPIRES_IN/PORT/UPLOAD_DIR`；
根 [.env.example](../.env.example) 含 `CMS_HTTP_PORT/CMS_DATA/JWT_SECRET/DEFAULT_ADMIN_USERNAME/DEFAULT_ADMIN_PASSWORD`。

> **结论：一致，无明显歧义。** 唯一"软差异"：`JWT_SECRET` 在代码内有弱默认值 `cms-super-secret-key`，
> 而生产 compose 用 `:?` 强制必填——属**有意为之**（开发方便 / 生产防呆）。

## 5. 歧义与缺陷清单

| # | 问题 | 证据 | 影响 | 严重度 |
|---|---|---|---|---|
| **1** | **同名不同单位**：`预计采购金额` | 采前会 `buildPreMeetingVariableValues` 取 `ctx.estimatedAmountWan`（**万元**，页面显示"万元"）；成交报告 `buildResultReportVariableValues` 取 `ctx.estimatedAmount`（**元**，页面显示"元"） | 同一 `{{预计采购金额}}` 在不同模块**单位不同** → 文档金额可能差 **10000 倍** | 🔴 高 |
| **2** | **同名不同源**：`采购编号` | 公告取 `data.procurementNo`（公告自身可编辑字段）；采购文件取 `ctx.procurementNo`（任务上下文） | 同变量名取到不同值 | 🟡 中 |
| **3** | **同概念不同名** | 采前会 `技术质量要求` / `验收标准` / `付款条件` ↔ 公告&文件 `技术质量标准` / `验收方式` / `付款方式`，均源于同一 `task.techQuality/acceptanceMethod/paymentMethod` | 模板作者选错名 → 占位符**静默不替换** | 🟡 中 |
| **4** | **定义了却永不替换**：INITIATE | `PROCUREMENT_MODULE_VARS.INITIATE` 有 3 个变量，但**无 `buildInitiate*VariableValues`**，且采购发起不产出 Word | 面板可插入，预览却永远高亮 | 🟡 中 |
| **5** | **单/双花括号混用 + 英文遗留 key** | 合同模板 `generate()` 曾同时替换 `{x}`、`{{x}}`、`{{MATERIAL_CODE_TABLE}}`、`{物料编码清单}` 等 | 语法不统一，认知负担 | 🟡 中 → **2026-10-14 已解决**（只保留 `{{x}}`） |
| **6** | **高亮函数只匹配单花括号** | [`highlightPlaceholders`](../web/src/utils/docExport.ts) 旧正则 `/\{([^{}]{1,30})\}/g`，对 `{{x}}` 靠匹配**内层** `{x}` 间接生效 | 脆弱；且任意 `{≤30 字文本}` 会被误高亮 | 🟢 低 → **2026-10-14 已解决**（只认 `{{x}}`） |
| **7** | **`物资产地` 归属混淆** | 仅存在于**合同模板变量**（varKey），**不在**采购公共变量；但 [.workbuddy/memory/MEMORY.md](../.workbuddy/memory/MEMORY.md) 称其为"采购公共变量" | 采购文档写 `{{物资产地}}` → 静默不替换 | 🟡 中 |
| **8** | **key/label 不一致** | [purchase-exec-contract.ts](../server/prisma/templates/purchase-exec-contract.ts)：`varKey: '银行名称'` 而 `varLabel: '开户银行'` | 展示名与取值名不符 | 🟢 低 |

### 结构性歧义（贯穿）

**两套占位符体系并存**（§2、§3）：同一个 `{{项目名称}}` 在**采购文档**与**合同模板**里
由**不同代码**替换、**规则不同**（采购有 table/html 类型标记；合同模板支持 varKey/sourceType）。
维护者与使用者都容易混淆"这个变量属于哪套、在哪能生效"。
（2026-10-14 起**语法已统一为 `{{变量名}}`**，但两套取值表仍是各自独立的两份实现。）

## 6. 修复建议（按优先级）→ 落地情况

> **本节已于 2026-10-13 全部实施**，逐项落点见 [§0.1 修复记录](#01-修复记录2026-10-13p1-已完成)。
> 下面保留原始建议原文，便于对照「建议 ↔ 实际做法」的差异。

1. **#1（最高）**：变量名带单位——改为 `预计采购金额(万元)` / `预计采购金额(元)`，或统一为「元」。
   若短期不改，至少在变量面板的 `tip` 里**显式标注单位**。
   → **已采纳「变量名带单位」**（保留两端各自的固有口径，比统一为「元」更不容易在既有模板上产生 10000 倍静默错值）。
2. **#3**：统一为 `技术质量标准` / `验收方式` / `付款方式`；或加**别名映射**兼容已用旧名的模板。
   → **两者都做**：规范名统一为公告侧命名，旧名进 `PROCUREMENT_VAR_ALIASES` 兼容替换。
3. **#4**：删除 `INITIATE` 的 3 个变量定义（采购发起无模板文档），或补上取值表。
   → **已删除**（该模块确实不产出 Word）。
4. **#2 / #7 / #8**：统一 `采购编号` 来源；把 `物资产地` 补进采购公共变量（或明确其仅属合同模板）；
   统一 key/label 命名。
   → **三条全采纳**：`采购编号` 以公告为源、空则回退任务编号；`物资产地` 补进采购公共变量；
   `varLabel` 与 `varKey` 对齐（不动 varKey 以免失效既有模板）。
5. **#5 / #6**：收敛为**单一花括号规范**（建议 `{{}}`）；合同模板的单花括号与英文遗留 key 加**废弃标记**，
   后续版本移除；修正 `highlightPlaceholders` 正则以同时正确匹配双花括号。
   → **2026-10-13**：规范定为 `{{}}` 并加废弃标注；`highlightPlaceholders` 修正为双括号优先、整段高亮。
   → **2026-10-14 收口**：用户确认**项目无存量业务数据、无需考虑兼容**，遂把兼容分支**彻底移除**：
   语法只认 `{{变量名}}`（渲染逻辑抽为零依赖纯函数 `template-render.ts` 并加 `templateRender.spec.mts` 回归锁），
   库中 4 份模板内容由迁移 `20261018000000_canonicalize_template_placeholders` 一次性规范化，
   下线的 `POST /templates/migrate`（英文 key 一键迁移，全仓无调用方）一并删除。
